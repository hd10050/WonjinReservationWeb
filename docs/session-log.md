> CLAUDE.md에는 최신 1건만 인라인으로 남기고, 나머지는 여기에 쌓는다. **삭제 금지.**

- **2026-08-26 (5) 요약 — 남은 설계 공백 7건 자율 결정·반영**: 사용자가 "알아서 하라"고 위임한 U2·U3·U8·U10·U11·U13·U16을 전부 결정해 문서화. 각 항목에서 **더 단순한 쪽**을 기본값으로 택했고, 그 근거를 문서에 남겼다.
  **U2 제출 성공 화면** — 별도 완료 페이지를 만들지 않고 폼 자리를 완료 안내로 교체(라우트를 늘리면 4언어 라우팅·noindex가 따라붙는데 얻는 게 없음). 안내에 예약 코드 + **입력한 위챗 ID 재확인**을 넣음 — 위챗ID 오타는 실장이 연락할 수단 자체를 잃는 유일한 치명 오류라, 이 화면이 마지막 방어선이다.
  **U3 error.vue** — 404/500을 화면 하나로 통합, 상태코드별 문구만 변경. 관리자 전용 에러 페이지는 만들지 않음. 4언어 + noindex.
  **U8 환경변수표**(4-3절 신설, 기존 브랜치 정책은 4-4로 이동) — 백엔드 8개·프론트 4개를 시크릿(🔑) 표시와 함께 정리. `NUXT_INTERNAL_SECRET`에 `NUXT_PUBLIC_` 접두사를 붙이면 브라우저 번들에 노출되어 방문수 조작 차단이 무력화된다는 경고 포함.
  **U10 RouteMap 매핑표**(14-1절) — 쓰기 엔드포인트 11행 전부. `/notes`·`/status`가 붙은 규칙은 세그먼트 2개라 `/api/admin/reservations` 단독 규칙과 **동시에 매치**되므로, 14장의 구체성 내림차순 정렬이 없으면 상담 기록 추가가 "예약 수정"으로 오분류된다 — 정렬 규칙이 실제로 필요한 사례를 표로 확인.
  **U11 i18n 키 규칙**(5-6절) — `<영역>.<화면>.<항목>` 최대 3단계. `status`·`errors`는 **DB 값·백엔드 에러 코드를 키로 그대로 사용**해 매핑 함수를 없앰(값이 추가될 때 한쪽만 갱신되는 사고 방지). 한 화면 전용 문구를 `common`에 넣지 말 것도 명시.
  **U13 rate limit 통합표**(7-5절) — auth(이메일+IP, 20/분) / refresh(사용자ID, 10/분) / reservation-create(IP, 5/분) / admin-write(사용자ID, 60/분) / 관리자 읽기·내부 엔드포인트는 제한 없음. 기존 정책 재사용 금지 원칙도 함께.
  **U16 테스트 전략**(19-1절) — **자동화 프레임워크 미도입**(CRUD·표시 로직 위주라 비용이 얻는 것보다 큼). 단 **동시성 결함 3종**(예약 코드 동시 생성 / 소프트 삭제와 상담기록 추가 경쟁 / 상태 전이 동시 요청)만 재현 스크립트를 남기고 결과를 세션 로그에 기록하기로 함 — 이 3개는 수동 클릭으로 재현 불가하고 운영에서 터지면 원인 추적이 거의 불가능한 종류라 예외로 뒀다. `curl` + `xargs -P` 수준이면 충분해 프레임워크가 필요 없다.

  **D15 소프트 삭제 설계**: `reservations.deleted_at`/`deleted_by_user_id` 추가 + **전역 쿼리 필터**(`HasQueryFilter`)로 목록·상세·달력·통계·KPI·유입경로 전환율에서 자동 제외(조회마다 손으로 조건을 붙이면 한 군데를 반드시 빠뜨림). 삭제 조건(상담 기록 0건)은 **`ExecuteUpdateAsync`의 WHERE 안에서 원자적으로 검사** — "조회 후 삭제" 2단계로 나누면 그 사이 다른 실장이 추가한 상담 내용째로 예약이 사라짐. 삭제 버튼은 상세 화면에만, 기록 0건일 때만 노출.
  **D16 주 단위 집계**: PostgreSQL `date_trunc('week', …)`가 ISO 기준 **월요일 시작**이라 일요일 시작으로 만들려면 `date_trunc('week', d + 1day) - 1day` 트릭이 필요. KST 변환 후 계산해야 주 경계가 안 어긋남. EF Core LINQ로 번역이 안 되므로 이 쿼리만 raw SQL(파라미터 바인딩). 검산까지 문서에 기록.
  **U1 재분류로 발견한 3건**: ①**미들웨어 무한 리다이렉트 버그** — 6-3절 코드가 미로그인 시 `/admin/login`으로 보내는데 그 페이지에도 미들웨어가 걸리면 자기 자신으로 계속 리다이렉트. `to.path === LOGIN_PATH` 조기 반환 추가. 별도 게스트 미들웨어를 만들지 말라는 경고도 함께(로그아웃 시 튕기는 사고 전례) ②**로그인 화면 언어 미정의** — 5-4절이 "관리자 화면 = 계정 locale"인데 로그인 전엔 계정을 모르는 자기모순. `wj_lang` 쿠키 → 없으면 한국어로 확정 ③**공유 IP rate limit** — 단일 병원이라 직원 전원이 같은 사무실 IP를 쓰는데 IP 분당 10회면 아침 동시 로그인에 정상 직원이 429로 막힘. `이메일+IP` 조합 파티션으로 변경(본문 버퍼링 필요 여부는 `[미확인]`, 어려우면 한도 상향).
  **남은 미답변**: U2(폼 제출 성공 화면)·U3(error.vue)·U8(환경변수 목록)·U10(감사 RouteMap 매핑표)·U11(i18n 키 규칙)·U13(rate limit 통합표)·U16(테스트 전략)은 사용자 지시가 없어 그대로 열려 있음.

  **설계 판단 근거 기록**: (a) 화면 깜빡임 금지 원칙을 SSR 프리로드로 이행하려면 SSR 요청에 인증 쿠키가 실려야 하므로 **동일 출처 API 프록시가 선택이 아닌 전제**임을 확인 — 부수 효과로 쿠키를 `SameSite=Lax`로 좁힐 수 있고 OAuth를 안 쓰므로 프록시 우회 예외 경로 문제도 없음. (b) 실장을 별도 테이블로 만들지 않고 `users.role='Consultant'` + 운영 컬럼 2개로 처리(1:1 관계 테이블은 과설계). (c) 유입 경로를 방문당 1행이 아니라 `(날짜 × 캠페인 조합)`당 1행 UPSERT로 설계해 광고 트래픽에도 행이 폭증하지 않게 함. (d) 시술명은 translations 테이블 대신 언어별 컬럼 4개 — 조인 제거 + DB 레벨 길이 제약 확보(언어 추가 시 마이그레이션 필요는 수용). (e) 연락 희망 시간을 자유 텍스트가 아닌 4지선다로 — 고객이 중국어로 자유 입력하면 한국인 실장이 해석 못 하는 실제 문제를 차단. (f) UI 라이브러리 미도입, 네이티브 `<dialog>`·`<input type="date">`·자체 월간 그리드로 처리.
  **지시 범위 준수**: "구현하지말고 설계파일을 남겨줘" 지시에 따라 **코드 구현은 일절 하지 않음**. git 저장소가 없어 `git init` + remote 연결 + 초기 커밋/push까지 수행.
